# Comparison bench: AgenticEnv against Claude Code

26 C++, CUDA and quantitative tasks, each graded by hidden checks the agent never sees.
It moved here from `~/testLLM` so the bench lives with the code it measures.
`benchmarks/agent/` stays the quick regression bench. This one is the hard one.

Results, regenerated by `harness/report.py`: [results/SUMMARY.md](results/SUMMARY.md).

## Layout

- `tasks/<id>/`: `prompt.md`, `task.json` (the checks), `fixture/` or `inject.patch`,
  `hidden/` (the grader) and `ref/` or `ref.patch` (a reference solution).
- `harness/run.py`: runs and grades. `drive_agenticenv.py` drives the sandbox the way the
  bridge does. `references*.py` computed the expected prices with QuantLib, independently of
  any agent. `resume_claude.py` retries runs lost to the subscription limit.
- `results/<task>/<agent>-r1/`: `summary.json`, `diff.patch`, and `events.jsonl` for AgenticEnv.

## Running

Rebuild the quant-modeling tree used by the `qm-*` tasks first. It is 3.7 GB, so it is not
versioned. `AGX_BENCH_WORK` moves it elsewhere; the default is `.work/` next to this file.

```bash
mkdir -p .work
git clone ~/quant-modeling .work/qm-base
git -C .work/qm-base checkout 3425ee04667d7f19f8db0d4ef9cda317c9855a48
git -C .work/qm-base rev-parse HEAD > .work/qm-base-sha
(cd .work/qm-base && cmake --preset default && ninja -C build quantModeling)
```

```bash
python3 harness/run.py baseline           # every check on the untouched fixture
python3 harness/run.py refcheck           # every check on the reference solution
python3 harness/run.py run --agent agenticenv --only mc-lsm
python3 harness/run.py run --agent claude --only mc-lsm
python3 harness/report.py
```

`run.py` overwrites `results/<task>/<agent>-r<rep>/`. Use `--rep 2` to keep a previous run.
Run it from a branch whose bridge is stopped or idle: opening or closing a chat session stops
every sandbox.

## Reading the results

- Each agent ran each task once, so one task difference is not significant.
- 16 Claude runs hit the subscription limit, and `mc-heston-qe` was interrupted before
  `resume_claude.py` saved anything. They are shown as `not run`. Their stored grades are what
  the untouched fixture scores, so `qm-fix-barrier` at 2/4 means nothing.
- AgenticEnv ran with Qwen3-Coder 30B, the served model at the time. Claude Code used its
  default model on the subscription, listed in each `summary.json`.
- `results/FROZEN.sha256` was recorded before the first run. Its input is not recorded, so it
  cannot be recomputed. Since then only paths changed, on the move here: the `source` lines of
  `check.sh`, `tasks/_lib/qm.sh`, `references2.py`, and two constants in `run.py`. Prompts,
  checks and expected values did not. `resume_claude.py` and `report.py` came later and do not
  touch grading.
